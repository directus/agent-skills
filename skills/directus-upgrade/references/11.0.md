# 11.0.0: policies and other breaking changes

The hop from 10.13.x to 11.0.0. Next: `11.x-minors.md`.

## Policies replace role permissions

**What.** Permissions live in **policies**, attached to roles and directly to users through `directus_access`. Roles
can nest (`directus_roles.parent`, `children`). A user's access is the union of policies on the user, their role, and
parent roles. The migration (`20240806A-permissions-policies`):

- Copies every role to a policy **with the same id**, name, icon, description, `admin_access`, `app_access`,
  `ip_access`, `enforce_tfa`, and attaches it to the role in `directus_access`.
- **Drops** `admin_access`, `app_access`, `ip_access`, `enforce_tfa` from `directus_roles`.
- Replaces `directus_permissions.role` with `policy`. Public permissions (`role IS NULL`) move to the Public policy, id
  `abf8a154-5b1c-4a46-ac9c-7300570f4f17`.
- Gives users a `policies` M2M field.

Access behaves the same; code reading or writing the old shapes breaks.

**Who.** Provisioning scripts, SDK calls on roles or permissions, admin dashboards, tests, seed data, app extensions
reading the user's role flags, flows that create roles.

**Detect.**

```bash
rg -n "admin_access|app_access|enforce_tfa|ip_access" -g '!node_modules' -g '!dist'
rg -n "directus_permissions|createPermission|readPermissions|updatePermission|/permissions" -g '!node_modules'
rg -n "filter\[role\]|role:\s*\{\s*_eq" -g '!node_modules'
rg -n "preRegisterCheck" extensions/ src/
rg -n "useUserStore|currentUser.*role" extensions/
```

**Fix.**

- Read admin and app access from the user (the app's `usersStore` user object) or `GET /policies` /
  `GET /users/me?fields=policies.*`, not `role.admin_access`.
- Create permissions with `policy: <policy id>`. To grant a role access, create a policy and `POST /access` with
  `{ role, policy }` (or `{ user, policy }`).
- `preRegisterCheck` receives the output of `GET /permissions/me` instead of permission rows.
- New filter variables `$CURRENT_ROLES`, `$CURRENT_POLICIES` (arrays). `$CURRENT_ROLE` still works.
- Use `@directus/sdk` 17+ (policy functions) against 11.x.

## Requests for missing fields fail

Asking for a field that doesn't exist throws instead of being ignored. Detect: run the app's main queries against a
staging 11 instance and watch for `INVALID_QUERY` / field errors. Fix: drop stale fields from `fields`, or restore them.

## M2A fields need the collection name

Nested fields inside a many-to-any must name the collection: `items.item.title` → `items.item:articles.title`. GraphQL:
per-collection fragment. Detect `rg -n "item\.[a-z_]+" -g '*.{ts,js,vue,tsx,jsx,graphql}'` and look for M2A `item`
paths without `:collection`.

## `mysql` driver replaced by `mysql2` (MySQL, MariaDB)

- Decimals come back as **strings**. Detect `rg -n "decimal|toFixed|parseFloat" src/` near decimal fields; parse on
  the client.
- Cross-collection filters compare charsets strictly. Make `DB_CHARSET` / `DB_CHARSET_NUMBER` match your tables.
