## License enforcement

**What.** Relicensed from BUSL-1.1 to MSCL-1.0-GPL, with entitlements enforced. Without a license a self-hosted
instance runs on the **core tier**: 3 seats (active users with App or Admin Access through any policy), 25 collections
(user collections incl. translation and junction tables), 5 flows, and these features off (`DIRECTUS_CORE_LICENSE` in
`@directus/license` 0.6.1, at 12.5.1):

| Feature                 | Without a license                                    | How Directus detects use                                                                                                                                                                |
| ----------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SSO                     | SSO login stops; convert SSO users to email/password | Active users with `provider` other than `default`                                                                                                                                       |
| Custom permission rules | Custom rules on policies are ignored                 | Non-system permission rows with item filters (`permissions`), `validation`, `presets`, or a `fields` list without `*` (including `NULL`), excluding the built-in app-access permissions |
| Custom LLMs             | Custom LLM connections stop                          | Any `ai_openai_compatible_*` setting is non-null                                                                                                                                        |
| AI translations         | Not available in the translations interface          | `ai_translations_enabled` entitlement, off on core                                                                                                                                      |

Over a limit, creating one more fails `403 LIMIT_EXCEEDED` with `extensions.category`. Tier details:
`directus-access-control`.

**Grace period.** An upgraded instance over core limits gets **30 days**, with a reminder on admin login. After that,
without a license, the resolution flow runs on next admin login and the instance locks down: `/items`, `/files`,
`/assets`, `/graphql`, `/mcp`, `/flows/trigger/:id` return `403 RESOURCE_RESTRICTED` (`extensions.category` names the
area), WebSocket upgrades are refused, non-admin login fails with category `login`. SSO still works for admins. Data
is never deleted; collections are set **Inactive** and users deactivated.

**Who.** Every self-hosted instance. Most affected: SSO, policies with item filters or field restrictions,
multi-tenant setups, OpenAI-compatible model settings, large schemas.

**Detect.** The [audit queries](#pre-upgrade-audit-queries) on the 11.x database, plus
`rg -n "AUTH_PROVIDERS|AUTH_.*_DRIVER" .env* docker-compose*`.

**Fix.**

- Get a license before upgrading. Existing customers: `licensing@directus.com`. Free commercial use under $5M revenue
  and under 50 employees: Open Innovation Grant (https://directus.com/oig).
- `PUBLIC_URL` must be absolute (the default `/` is rejected at activation).
- `LICENSE_KEY` in the env (or **Settings > License**). `LICENSE_TOKEN` is offline, Enterprise only. Setting both
  stops Directus from starting.
- Allow outbound HTTPS to `https://licensing.directus.com` (online mode).
- After upgrading, `GET /license` (admin) shows status and usage.

**House rule:** deactivate a license before destroying an instance it is bound to, including throwaway upgrade test
environments. Stranded activations count against the activation limit.

## Pre-upgrade audit queries

Run on 11.x. Approximations of the 12.x checks; after upgrading, trust `GET /license` (admin).

```bash
# Collections that count: has a table, has Directus metadata, not a system collection
curl -s -H "Authorization: Bearer $TOKEN" "$URL/collections" \
  | jq '[.data[] | select(.schema != null and .meta != null and (.collection | startswith("directus_") | not))] | length'
# Active flows
curl -s -g -H "Authorization: Bearer $TOKEN" "$URL/flows?filter[status][_eq]=active&fields=id&limit=-1" | jq '.data | length'
```

```sql
-- PostgreSQL syntax; "user" is a reserved word, quote it on Postgres.
-- Seats (approximate: ignores nested roles): active users with app or admin access via user or role policies
SELECT count(DISTINCT u.id) FROM directus_users u
JOIN directus_access a ON a."user" = u.id OR a.role = u.role
JOIN directus_policies p ON p.id = a.policy
WHERE u.status = 'active' AND (p.app_access OR p.admin_access);
-- SSO users
SELECT provider, count(*) FROM directus_users WHERE provider <> 'default' AND status = 'active' GROUP BY provider;
-- Candidate custom permission rules (Directus also excludes the built-in app-access rows, and treats an empty {} as
-- no rule). fields NULL counts: v12 hides and ignores those rows on core just like a field list.
SELECT policy, collection, action, fields FROM directus_permissions
WHERE permissions IS NOT NULL OR validation IS NOT NULL OR presets IS NOT NULL
   OR fields IS NULL OR (',' || fields || ',') NOT LIKE '%,*,%';
-- Custom LLM settings: any non-null column counts (columns exist on late 11.x). Doesn't print the key or headers.
SELECT ai_openai_compatible_base_url, ai_openai_compatible_name, ai_openai_compatible_models,
       ai_openai_compatible_api_key IS NOT NULL AS has_api_key,
       ai_openai_compatible_headers IS NOT NULL AS has_headers
FROM directus_settings;
```

## `IP_TRUST_PROXY` defaults to `false`

Was `true`; `X-Forwarded-For` is ignored unless you opt in. Who: anything behind a reverse proxy, load balancer, or
CDN. Every request appears to come from the proxy IP, so rate limiting, policy IP access, and activity logs use the
wrong IP. Detect `rg -n "IP_TRUST_PROXY" .env* docker-compose* *.yaml` (no hit plus a proxy means affected). Fix: set
`IP_TRUST_PROXY` to the hop count (`1`) or the proxy's CIDR. Not `true`: that trusts any client-sent
`X-Forwarded-For`, so clients can pick their own IP. See `directus-self-hosting` configuration.

## `/server/health` requires a token

- **What:** unauthenticated requests get **403 `FORBIDDEN`**. Non-admins get only `status`; admins the full report.
  Results cached for `HEALTHCHECK_CACHE_TTL` (default `5m`), shared across instances. The `cache`, `rateLimiter`,
  `rateLimiterGlobal` checks become one `redis` check (`redis:` prefix). `HEALTHCHECK_ENABLED` (default `true`) and
  `HEALTHCHECK_SERVICES` (default `database,redis,storage,email`) control it.
- **Who:** Docker `HEALTHCHECK`, Kubernetes probes, load balancer target groups, uptime monitors, dashboards reading
  check names.
- **Detect:** `rg -n "server/health" -g '!node_modules'`; `rg -n "rateLimiter|rateLimiterGlobal|cache:responseTime" -g '!node_modules'`.
- **Fix:** liveness probes → `/server/ping` (public, returns `pong`, no dependency checks). Dependency checks → keep
  `/server/health` with a static token. Update monitors to the `redis:` check names.

## Content versioning: `published` and `draft`

- **What:** `?version=published` returns the published item; `?version=main` still works as a legacy alias. Published
  items in versioned collections are locked from direct editing in the Studio: edits go through the draft version, and
  creating an item opens a virtual draft (`collection/+?version=draft`). Publishing has no second confirmation dialog.
- **Who:** frontends and preview code passing `version=main`; editorial workflows expecting direct edits.
- **Detect:** `rg -n "version[=:]\s*['\"]?main" -g '!node_modules'`; `rg -n "versionRaw|_by_version" -g '!node_modules'`.
- **Fix:** `version: 'published'` in new code; handle both `published` and `main` where you compare keys
  (`VERSION_KEY_PUBLISHED`, `VERSION_KEY_PUBLISHED_LEGACY`, `VERSION_KEY_DRAFT` in `@directus/constants`). Preview and
  live preview read `version=draft`.

## Collection `archived` boolean

New collections default to a boolean **Archived** field instead of a string **Status** field. Existing collections keep
`status`. Code assuming every collection has `status` should check the schema. No migration needed.

Also new in 12.0.0: `MCP_OAUTH_ENABLED` (default `false`).

## SDK 22: errors are `RequestError` instances

In the 12.0.0 release notes, not the docs breaking-changes page. `@directus/sdk` 22.0.0 rejects failed requests with a
`RequestError` (an `Error` subclass with `errors`, `response`, optional `data`) instead of a plain object.
`isDirectusError()` still works. `updateExtension` takes an `id` instead of `bundle` and `name`.

```bash
rg -n "catch\s*\(\s*\w+\s*\)" -g '*.{ts,tsx,js,vue}' | rg -v node_modules   # then look for spreads or JSON.stringify of the error
rg -n "\.\.\.(err|error|e)\b|JSON\.stringify\((err|error|e)\)" -g '!node_modules'
rg -n "updateExtension\(" -g '!node_modules'
```

Fix: read `error.errors[0].message` / `error.errors[0].extensions.code` (unchanged), guard with
`isDirectusError(error)`. Don't spread or `JSON.stringify` the error expecting its fields. `updateExtension(id, data)`.

## Theme and app extension changes

Studio redesign. Theme extensions keep loading; removed properties silently stop applying.

| Removed                                                                                                                                                                     | Replacement                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `navigation.background`, `navigation.backgroundAccent`, `navigation.borderWidth`, `navigation.borderColor`, `header.background`, `header.borderWidth`, `header.borderColor` | `shell.background`, `shell.backgroundAccent`, `shell.borderWidth`, `shell.borderColor` |
| `header.headline.foreground`, `header.headline.fontFamily`                                                                                                                  | none                                                                                   |
| `headerShadow`, `sidebarShadow` (`LayoutConfig`, `defineLayout()`), `boxShadow` (header rules)                                                                              | none                                                                                   |
| `section.toggle.borderWidth`, `section.toggle.borderColor`                                                                                                                  | section-level border tokens                                                            |
| `navigation.project.borderColor`, `.borderWidth`, `.background`                                                                                                             | none                                                                                   |
| `borderColorFocus`, `boxShadowHover`, `boxShadowFocus`                                                                                                                      | focus ring tokens (CSS `outline`)                                                      |

CSS variables follow the same map; only the removed keys moved. `--theme--navigation--background`,
`--theme--navigation--background-accent`, `--theme--navigation--border-*`, `--theme--header--background`,
`--theme--header--border-*` → `--theme--shell--*`. Gone: `--theme--header--box-shadow`, `--theme--header--headline--*`,
`--theme--navigation--project--background` / `--border-*`. Still valid: `--theme--header--title--*`,
`--theme--navigation--modules--*`, `--theme--navigation--list--*`, `--theme--navigation--project--foreground` /
`--font-family`. `--theme--form--field--input--border-color-focus` and `--theme--form--field--input--box-shadow-focus` →
`--theme--form--field--input--focus-ring-color`.

Deprecated (still render, Volar hints): `<v-resizeable>` (use `@directus/vue-split-panel`), `<v-breadcrumb>`,
`v-drawer` `subtitle` prop and slot, `header:append` and `actions:append` slots (use `actions:primary`), header bar
`#headline` slot. `v-button` `rounded` prop removed (renders as rounded rectangle).

```bash
rg -n "navigation\.(background|border|project)|header\.(background|border|headline)|headerShadow|sidebarShadow|boxShadowFocus|boxShadowHover|borderColorFocus|section\.toggle" extensions/
rg -n "\-\-theme\-\-(navigation\-\-(background|border)|navigation\-\-project\-\-(background|border)|header\-\-(background|border|box-shadow|headline))|border-color-focus|box-shadow-focus" extensions/
rg -n "v-resizeable|v-breadcrumb|#headline|actions:append|header:append|<v-button[^>]*rounded" extensions/
```
